# Artistic Gymnastics

Система проведения соревнований по спортивной гимнастике: сервер в зале собирает оценки судей со страниц на снарядах, считает результаты по правилам FIG и в реальном времени передаёт их на сайт.

## Структура

| Пакет | Назначение |
| --- | --- |
| `packages/scoring` | Подсчёт по правилам FIG: оценка за выступление, опорный прыжок, многоборье, команды, места |
| `packages/shared` | Схемы запросов и событий, общие для сервера и страниц |
| `apps/server` | Сервер в зале: участники, судьи, приём оценок, утверждение, результаты, Socket.IO |
| `apps/judge` | Страницы судей на планшетах и выдача QR-кодов в секретариате |
| `apps/scoreboard` | Табло в зале: кто выступает, последние оценки, таблицы мест. Эта же сборка — виджет для сайта |
| `apps/relay` | Облачный ретранслятор: принимает результаты из зала и раздаёт их сайту |

Дальше появится `apps/admin`.

## Запуск сервера в зале

Нужен Docker. Запуск одной командой: `scripts\start.ps1` на Windows (правой кнопкой → «Выполнить с помощью PowerShell») или `scripts/start.sh` на Linux и macOS. При первом запуске скрипт создаёт `.env` с токеном секретариата и показывает адреса для секретариата и табло.

Сервер слушает порт 3000 и при старте сам применяет миграции базы. Резервная копия базы снимается каждые 5 минут в папку `backups`; восстановление — `scripts/restore.sh` или `scripts\restore.ps1`. Памятка на день соревнований: [docs/competition-day.md](docs/competition-day.md).

- Секретариат: `http://<адрес сервера>:3000/judge/#/admin` — создаёт соревнование и выбирает правила судейства (FIG или свои: база по разряду минус сбавки), загружает заявки клубов из Excel или вставляет список участников из таблицы (№ · Фамилия · Имя · Клуб · Команда · Разряд · Смена · Дата рождения · Город · Тренер · Отчество), правит любые данные участника, проводит жеребьёвку стартовых номеров (случайную или ручную), задаёт стартовые снаряды смен и переводит смены на следующую ротацию, заводит судей и печатает им QR-коды (для снаряда с одним планшетом — один QR-код старшему судье), печатает стартовый протокол, судейские ведомости и протоколы в PDF с логотипом соревнования, выгружает итоги в Excel, печатает грамоты призёрам, записывает запросы тренеров на пересмотр оценки D и вносит решения жюри.
- Судья сканирует свой QR-код планшетом и попадает на страницу своего снаряда.
- Табло: `http://<адрес сервера>:3000/board/` на большом экране, в полноэкранном режиме браузера (F11). API описано в [apps/server/README.md](apps/server/README.md).

## Результаты на сайте

Зал и сайт связаны через ретранслятор в облаке: сервер в зале сам отправляет ему результаты после каждого вызова участника и каждой утверждённой оценки, а зрители сайта получают обновления от ретранслятора и никогда не обращаются к залу напрямую. Если интернет в зале пропал, сервер копит изменения и отправит последний снимок, когда связь вернётся.

1. Разверните ретранслятор на любом сервере с публичным адресом, как описано в [apps/relay/README.md](apps/relay/README.md).
2. В `.env` сервера в зале впишите `RELAY_URL` (адрес ретранслятора) и `RELAY_TOKEN` (тот же токен, что у ретранслятора) и перезапустите `docker compose up -d`.
3. На страницу сайта вставьте:

```html
<div data-ag-results="ID соревнования" data-view="auto" data-theme="light"></div>
<script src="https://АДРЕС-РЕТРАНСЛЯТОРА/embed.js" async></script>
```

ID соревнования виден в адресе табло после `#c=`. `data-view`: `auto` (экраны по очереди), `now` (сейчас на снарядах), `aa` (многоборье), `teams` (команды) или код снаряда (`FX`, `VT`, `BB`…). `data-theme`: `light` или `dark`.

## Разработка

Нужны Node.js 22 и pnpm 10.

```sh
pnpm install
pnpm build
pnpm typecheck
pnpm test   # тестам сервера нужен PostgreSQL, адрес берётся из DATABASE_URL
```

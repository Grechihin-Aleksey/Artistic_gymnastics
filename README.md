# Artistic Gymnastics

Система проведения соревнований по спортивной гимнастике: сервер в зале собирает оценки судей со страниц на снарядах, считает результаты по правилам FIG и в реальном времени передаёт их на сайт.

## Структура

| Пакет | Назначение |
| --- | --- |
| `packages/scoring` | Подсчёт по правилам FIG: оценка за выступление, опорный прыжок, многоборье, команды, места |
| `packages/shared` | Схемы запросов и событий, общие для сервера и страниц |
| `apps/server` | Сервер в зале: участники, судьи, приём оценок, утверждение, результаты, Socket.IO |
| `apps/judge` | Страницы судей на планшетах и выдача QR-кодов в секретариате |
| `apps/scoreboard` | Табло в зале: кто выступает, последние оценки, таблицы мест. Эта же сборка — виджет для сайта |
| `apps/relay` | Облачный ретранслятор: принимает результаты из зала и раздаёт их сайту |

Дальше появится `apps/admin`.

## Запуск сервера в зале

Нужен Docker. На Windows программа запускается двойным щелчком по `Запуск.bat` в папке программы (он сам открывает Docker Desktop, если тот закрыт), на Linux и macOS — `scripts/start.sh`. При первом запуске скрипт создаёт `.env` с токеном секретариата, спрашивает адрес и токен сайта (можно пропустить) и показывает адреса для секретариата и табло. Обновление до последней версии на Windows — двойной щелчок по `Обновить.bat`: турниры, `.env` и резервные копии сохраняются.

Сервер слушает порт 3000 и при старте сам применяет миграции базы. Резервная копия базы снимается каждые 5 минут в папку `backups`, а каждый турнир каждые полчаса сохраняется файлом в `backups/tournaments`; восстановление — `scripts/restore.sh` или `scripts\restore.ps1`. Памятка на день соревнований: [docs/competition-day.md](docs/competition-day.md).

- Секретариат: `http://<адрес сервера>:3000/judge/#/admin` — создаёт соревнование и выбирает правила судейства (FIG или свои: база по разряду минус сбавки), принимает онлайн-заявки клубов по ссылке на сайте, загружает заявки клубов из Excel или вставляет список участников из таблицы (№ · Фамилия · Имя · Клуб · Команда · Разряд · Смена · Дата рождения · Город · Тренер · Отчество), правит любые данные участника, проводит жеребьёвку стартовых номеров (случайную или ручную), формирует финалы на отдельных снарядах по итогам квалификации (с запасными и лимитом от клуба), задаёт стартовые снаряды смен и переводит смены на следующую ротацию, заводит судей и печатает им QR-коды (для снаряда с одним планшетом — один QR-код старшему судье), печатает стартовый протокол, судейские ведомости и протоколы в PDF с логотипом соревнования, выгружает итоги в Excel, печатает грамоты призёрам, ведёт общекомандный зачёт клубов по очкам за места, выводит пьедестал награждения на табло, ведёт журнал изменений оценок и данных с выгрузкой для жюри, выкладывает итоговые протоколы на сайт, подводит итоги кубка из нескольких этапов, нагрудные номера, состав судейской коллегии, список выполнивших разряды и итоговый отчёт, записывает запросы тренеров на пересмотр оценки D и вносит решения жюри, вводит оценки с судейских листов, когда планшеты без связи, исправляет и удаляет любую оценку, переносит турнир на другой компьютер одним файлом и удаляет турнир целиком.
- Судья сканирует свой QR-код планшетом и попадает на страницу своего снаряда.
- Табло: `http://<адрес сервера>:3000/board/` на большом экране, в полноэкранном режиме браузера (F11). API описано в [apps/server/README.md](apps/server/README.md).

## Результаты на сайте

Турнир, где выступают и девочки, и мальчики, создаётся программой «Девочки и мальчики»: это две связанные части со своим подсчётом (у девочек 4 снаряда, у мальчиков 6). В секретариате это одна строка в списке соревнований с переключателем «Девочки | Мальчики», список участников загружается один раз и делится по столбцу «Пол» (Ж или М), а на сайте обе части показываются в одной рамке с переключателем.

Зал и сайт связаны через ретранслятор в облаке: сервер в зале сам отправляет ему результаты после каждого вызова участника и каждой утверждённой оценки, а зрители сайта получают обновления от ретранслятора и никогда не обращаются к залу напрямую. Если интернет в зале пропал, сервер копит изменения и отправит последний снимок, когда связь вернётся. Значок «Сайт» в шапке секретариата зелёный, пока результаты доходят до сайта, и красный с причиной, если нет. На экране «Соревнование» панель «Результаты на сайте» отправляет турнир на сайт сразу, не дожидаясь первой оценки, и даёт готовый код для вставки на страницу сайта.

1. Разверните ретранслятор на любом сервере с публичным адресом, как описано в [apps/relay/README.md](apps/relay/README.md).
2. В `.env` сервера в зале впишите `RELAY_URL` (адрес ретранслятора) и `RELAY_TOKEN` (тот же токен, что у ретранслятора) и перезапустите `docker compose up -d`.
3. На страницу сайта вставьте:

```html
<div data-ag-results="ID соревнования" data-view="auto" data-theme="light"></div>
<script src="https://АДРЕС-РЕТРАНСЛЯТОРА/embed.js" async></script>
```

ID соревнования виден в адресе табло после `#c=`. `data-view`: `auto` (экраны по очереди), `now` (сейчас на снарядах), `aa` (многоборье), `teams` (команды) или код снаряда (`FX`, `VT`, `BB`…). `data-theme`: `light` или `dark`.

## Разработка

Нужны Node.js 22 и pnpm 10.

```sh
pnpm install
pnpm build
pnpm typecheck
pnpm test   # тестам сервера нужен PostgreSQL, адрес берётся из DATABASE_URL
```
